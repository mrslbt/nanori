Site defect (supported by evidence) Proposed by Claude, not yet reviewed

long-name-spaces · お名前 (name=flname) · rejected

What nanori entered
Maria Clara Santos Dela Cruz
What the field kept
Maria Clara Santos Dela Cruz
What the page reported
文字数が正しくありません。
Observation
The single お名前 field kept the full 28-character name but showed the error 文字数が正しくありません。 next to it, and the agent stopped before the confirmation screen. The agent also reported that the time select showed no options, which was not measured and is not part of this finding.
Relevance
A person with a name of this shape, with two middle names and a compound family name, is an intended user of a contact form. The baseline name 山田 太郎 and shorter Latin names (16 characters, with spaces, diacritics and hyphens) all reached confirmation, so the rejection is tied to this name's length.
Basis
This is inconsistent with p.27 item 4 of the guidance, which says to set a sufficient maximum length because foreign names need more characters. It also conflicts with item 1, which says one full-name field should fit middle and compound names. (applicable recommendation, GovTech Tokyo Input Form Guidance v1.1, p.27 item 4 (sufficient maximum length); also item 1 (one full-name field accommodates middle and compound names))
Cause
A character-count rule rejects the name somewhere between 17 and 28 characters, as the error text states. No maxlength or pattern attribute was visible in the DOM, so this cause is reproduced from behaviour and not confirmed in source.
Proposed repair
Raise the length limit in the site's name validation (JS and server) to at least 100 characters, and add a matching maxlength="100" on input[name=flname] so the limit is visible. Keep the empty-value check and the over-limit rejection so invalid input is still refused.
