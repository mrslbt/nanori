What happened
The お名前 field kept the full 28-character name but was marked aria-invalid, and the site showed "文字数が正しくありません。" (the character count is incorrect), so the agent could not reach the confirmation screen. The Japanese-name baseline passed this step and reached the confirmation screen.
Why it matters
A person with a name of this shape, a multi-part Latin-script name with spaces, has a long full name that cannot be shortened without changing it. Such a person is an intended user of a form that collects a name.
Basis
Rejecting the name on character count is inconsistent with p.27 item 4 of the guidance, which says to set a sufficient maximum length because foreign names need more characters. The guidance applies to Tokyo Metropolitan Government forms, so for this site it is a reference point, not a rule. (applicable recommendation; GovTech Tokyo Input Form Guidance ver 1.1, p.27 Name, item 4 (sufficient maximum length))
Cause
The rejection is reproduced from behaviour, not confirmed in source: the field has no maxlength or pattern attribute, so a script or server-side length check produced the error. The agent reported that the page states a 20-character limit, but nanori did not measure that limit.
Proposed repair
Raise the name length limit in the validation code that emits "文字数が正しくありません。" to a generous value such as 100 characters, and add a matching maxlength="100" on input[name=flname]. Keep rejecting empty and over-limit values. This change is unverified against the live site.
