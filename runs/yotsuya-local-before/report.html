What happened
The site showed 文字数が正しくありません。 next to the single お名前 field and set aria-invalid after a 28-character name was entered, so the form did not advance to the confirmation screen. The field kept the full value, and the baseline Japanese name reached the confirmation screen without this error.
Why it matters
A person with a name of this shape, with two middle names and a compound family name, writes it in Latin letters with spaces and needs more than 20 characters. The error text refers to character count, so the length rule acted on the name itself.
Basis
This is inconsistent with p.27 item 4 of the guidance, which says to set a sufficient maximum length because foreign names need more characters. The site's own pages are not bound by this Tokyo guidance, so this is stated as an inconsistency only. (applicable recommendation; GovTech Tokyo Input Form Guidance v1.1, p.27, Name item 4 (sufficient maximum length))
Cause
No maxlength or pattern attribute was in the DOM, so the cause is reproduced from behaviour, not confirmed in source. The agent reported that the page states a 20-character maximum; nanori did not measure that text, and it does not offer another way to enter the name.
Proposed repair
Raise the お名前 length limit in the client script and on the server from 20 to at least 100 characters, for example maxlength="100" with the same check on the server. Keep rejecting empty values and values over the new limit.
