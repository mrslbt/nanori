What happened
The single お名前 field kept the full 28-character value "Maria Clara Santos Dela Cruz" but showed the site error 文字数が正しくありません。 (character count incorrect), and the form did not reach the confirmation screen. The Japanese baseline and shorter Latin names with spaces, such as "Ana García-López" and "Nguyễn Thị Hương" (16 characters each), all reached confirmation.
Why it matters
A person with a long multi-part name of this shape is an intended user of a public contact form. Middle and compound names often produce full names well over 20 characters when written in Latin letters.
Basis
Rejecting a name only because of its length is inconsistent with p.27 item 4 of the GovTech Tokyo guidance, which asks for a sufficient maximum length because foreign names need more characters. This guidance is scoped to Tokyo Metropolitan Government forms and is not a law. (applicable recommendation; GovTech Tokyo Input Form Guidance v1.1, p.27 item 4 (sufficient maximum length))
Cause
The DOM shows no maxlength or pattern attribute on the field, so the length limit is enforced by script or server; this cause is reproduced from behaviour, not confirmed in source. The limit lies somewhere between 17 and 27 characters, because 16-character names were accepted and the 28-character name was rejected.
Proposed repair
Raise the name length limit in the validation that emits 文字数が正しくありません。 to a generous bound (for example 1 to 100 characters), and keep rejecting empty or overlong input. This is a suggested change based on behaviour; it has not been verified against the site's own code.
The repair brief as text

Separate boundary probe (same page, fixed inputs, only the name length varied): 20 characters accepted, 21 rejected, for the tested strings; the server implementation was not inspected. probe evidence. The model-written cause above was captured before this probe and is left as recorded.
