What happened
The given-name field kept the 18-character value "Maria Clara Santos" but marked it invalid (aria-invalid) and showed "10文字以内で入力してください。", so the confirmation screen was not reached. The baseline name 山田 太郎 passed the same form and reached confirmation.
Why it matters
A person with a name of this shape (several given names plus a compound surname) is an intended user of a name form. Any reasonable split of this 28-character name puts more than 10 characters in at least one field, so they cannot proceed.
Basis
A 10-character limit on a name part is inconsistent with p.27 item 4, which asks for a sufficient maximum length because foreign names need more characters. The page gives no number, and the split surname/given-name layout also differs from item 1's single full-name field. (applicable recommendation; GovTech Tokyo Input Form Guidance ver 1.1, p.27 Name, item 4 (set a sufficient maximum length, because foreign names need more characters))
Cause
A validation rule limits the given-name field to 10 characters; no maxlength or pattern attribute was present in the DOM, so this is reproduced from behaviour, not confirmed in source. The rule acted on length alone, as the error text names only the character count.
Proposed repair
Raise the length check for the name fields (client script and server) from 10 to a generous limit such as 50 characters (a demonstration choice), while still rejecting empty values and strings over that limit. Better still, offer one full-name field per p.27 item 1; verify on a local reproduction, not the live site.
